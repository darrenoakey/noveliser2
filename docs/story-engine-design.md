# Causal story engine — design before implementation

## Existing pipeline and gap

`description → Booker type → themes → cast → freeform outline → humor/romance enhancement → style → chapter plans → section plans → prose → EPUB` is resumable through raw JSON checkpoints. Prose sees the cast, recent text and retrieved prior sentences. This continuity mechanism stays. `craft.py` already *asks* for Want/Need, three-act beats, scene/sequel and therefore/but, but schema only records five character attributes, opening/closing/key events per chapter and goal/key events/disaster per section. Thus a plan can satisfy every field without an action causing the next action.

## Design

Booker, Hero's Journey, three-act and Save the Cat are optional diagnostic lenses, not plot generators or fixed page percentages. Snowflake's useful contribution is progressive expansion: retain the existing stages, but make each expansion a falsifiable causal commitment. Each chapter carries the actor's immediate pursuit, specific opposition, jeopardy, choice/cost, reversal or revelation, before/after value, an explicit link to prior consequence, setup/payoff identifiers, subplot/relationship change and an open reader question. Each section records scene/sequel dynamics with POV, obstacle, dilemma/decision or disaster, changed value, cause of entry and next obligation. The cast records behavioral flaw, distinctive voice, and relationship/arc pressures; private truth is dramatized rather than narrated.

First run structural validation on generated chapter/section plans: exact counts/number order; essential causal fields nonempty; explicit incoming/outgoing links after the first beat; no payable setup without an earlier plant; named character actors; and a changed end state. Reject and regenerate with *specific* deficiencies (bounded retries), never silently save a hollow plan. Existing cached plans remain loadable and keep original continuity semantics; newly generated plans cannot bypass validation. A separate prose check examines minimum substantive length and meta-text; reject/rewrite boundedly while preserving retrieval-memory idempotence (only embed accepted text). Do not use lexical cliche detectors as sole arbiters: fiction can employ repetition intentionally.

## Scope and evidence to collect

Compare identical planning and prose tasks on available remote local runtimes, repeated independent seeds, actual tokens/sec and checkpoint/quant/runtime, with blinded human-readable side-by-sides. Assess character-specific voice, causal choice/cost, revelation, continuity, dialogue, cliche/purple prose and instruction adherence separately; generic model-as-judge scores are not truth. Gate a brief pilot before the full commissioned magician novel. Keep output directories resumable; document all results and sources here once verified.

## Implemented (GOAL 1)

- `src/models.py`: all new fields are defaulted, so old raw checkpoints load unchanged. `Character` gains `flaw`, `voice`, `arc_pressure`, `relationships[]` (`Relationship{other,dynamic,pressure}`). `Chapter` gains `pov_character`, `cause_from_previous`, `pursuit`, `opposition`, `stakes`, `choice`, `cost`, `reversal`, `value_before/after`, `setups`, `payoffs`, `subplot`, `subplot_change`, `open_question`; `ChapterPlan` gains `central_question`, `subplots`. `Section` gains `pov_character`, `cause`, `obstacle`, `choice`, `cost`, `value_before/after`, `setups`, `payoffs`, `next_obligation`.
- `src/story_validation.py`: deterministic `validate_characters`, `validate_chapter_plan`, `validate_section_plan`, `validate_prose` return specific deficiency strings; `plan_with_feedback` retries at most 3 times, feeding the exact deficiencies back as an appended user message (generation ValueErrors such as wrong counts are fed back too) and raises `StoryPlanError` instead of saving a hollow plan. Only newly generated plans are validated; cached plans are never re-validated.
- `create_characters`, `break_into_chapters`, `break_into_sections` (now takes optional `characters`; omitted = no validation) use it. Setups planted in earlier chapters are the only legal chapter-/section-level payoffs; non-final setups must be paid later.
- `write_section` renders the richer cast/chapter/section causality into the prose prompt and rewrites boundedly (3 attempts) if prose is too short (<600 words) or contains meta-text/headers; it returns only accepted text, so the pipeline's `memory.ensure_section` embeds each section once and retrieval memory is unchanged. Repetition/cliche is deliberately not detected.
- Tests: `src/test_story_validation.py` (real objects, no mocks; legacy checkpoint load; bounded replanning).

## Operational note

Controlled multi-model evaluations, premise-guarded outline/schedule pilots, and full-book generation routinely exceed a single agent turn and must always be launched as detached one-shot processes with durable log/exit files. Park the turn with sleep and inspect outputs on wake. Do not run them as blocking tool calls or poll continuously.

## Research basis and trade-offs (2026-10-02)

Three-act structure [Reedsy](https://reedsy.com/blog/guide/story-structure/three-act-structure/), [Hero's Journey](https://reedsy.com/blog/guide/story-structure/heros-journey/), [Save the Cat](https://savethecat.com/beat-sheets) and [Booker's taxonomy](https://www.bloomsbury.com/us/seven-basic-plots-9780826452092/) supply optional editorial viewpoints, not a mandatory timetable or one-plot classifier. The [Snowflake method](https://www.advancedfictionwriting.com/articles/snowflake-method/) supports our existing staged expansion. [Scene/sequel](https://www.helpingwritersbecomeauthors.com/scene-structure/) contributes goal/conflict/turn and reaction/dilemma/decision, not strict alternation. [Character arcs](https://reedsy.com/blog/character-arc/) need behavioral pressure and evidence, not labels alone; [Chekhov's gun](https://reedsy.com/blog/chekhovs-gun/) makes *salient promises* payable, without requiring every atmospheric detail to recur. [Mystery design](https://reedsy.com/studio/resources/how-to-write-a-mystery/) calls for reader-facing clues before a reveal; this iteration represents those as named setup/payoff ids but does not yet implement a full suspect/fairness registry.

The schema stores required dramatic choices on newly generated plans and validates structural holes with three bounded feedback attempts. Compatibility fields default to empty for historical checkpoints and are not retroactively rejected. The enhancement stage no longer mechanically inserts a romance or joke. Retrieval memory remains the prose continuity source; plan IDs add intentional obligations without pretending vector matches prove causality. This validator checks presence and sequencing, not semantic truth; editorial inspection is still required. Future graph edges and formal mystery fairness checks would need their own tests and explicit user-facing authoring semantics.

For evaluating prose, [LitBench (Fein et al., EACL 2026)](https://aclanthology.org/2026.eacl-long.362/) found generic off-the-shelf judges imperfect (~73% best reported agreement on its human labels); preserve blinded side-by-side examples and do not present a model score as objective literature quality. On available hardware, direct remote Ollama 0.35.0 on the 128-GiB Boringstack M5 Max avoids loading a model on the RAM-constrained laptop or directly on shared Spark. Installed GGUF candidates: `qwen3.6:35b-a3b` Q4_K_M 22.62 GB, `qwen3.8:27b` Q4_K_M 17.74 GB, `ornith-1.5:35b` Q4_K_M 22.62 GB and `gemma4:26b` Q4_K_M 18.60 GB. Relevant model cards: [Qwen3.8](https://ollama.com/library/qwen3.8), [Qwen3.5 official](https://huggingface.co/Qwen/Qwen3.5-35B-A3B), [DiscoverLLM writing LoRA](https://huggingface.co/kixlab/DiscoverLLM-creative-writing-Qwen3-8B); the last two are not installed drop-in comparators and cannot win without actual evaluation.

## Empirical revision of the design

A later live pilot showed two separate failures. Chapter repair appended setup IDs when the deficiency named only the ID, so schedule evidence failures now quote the exact plant, payoff, or handoff sentence that must be pasted unchanged. The same pilot outline also invented a predecessor who performed real magic and replaced the floodgate cover-up with a witch hunt. The three-chapter pilot then passed: a frozen schedule stayed inside three chapters, the floodgate payoff landed in chapter 3, and two Ornith prose sections (2701 and 1378 words) dramatized the coin-through-oak cost and concealment without a second real magician. The acceptance novel is therefore an 8-chapter, 5-section book, not the default 100-scene run, generated detached through `scripts/acceptance_novel.py`. On 2026-10-01 the run stopped after the title checkpoint because Boringstack (`10.0.0.42`, DHCP name boringstack, MAC `B6:A4:AD:43:12:46`) was off the LAN and did not answer a router `ether-wake`. Do not load the 35B models on the laptop. Resume with `python3 scripts/acceptance_novel.py output/The_Weight_of_Wonder` once `http://10.0.0.42:11434/api/tags` answers. The first live acceptance pilot disproved the assumption that adding Pydantic fields automatically makes the model fill them: a structured cast emitted blank Want/Need/voice and four protagonists. Legacy-compatible defaults stay on the checkpoint models, while the **generation-only** schemas now require populated character/scene fields and machine-valid ages. The bounded repair prompt includes the *exact rejected draft* as well as field-specific failures; otherwise the model cannot repair its own IDs and causality. Chapter validation now requires a payoff to cite an earlier plant, requires both events to actually name that clue/object, and forbids silently re-planting the same ID in later chapters. Optional incidental details are not promises. This was observed in actual Qwen/Ornith structured calls, not inferred from unit fixtures. A cast with a fourteen-year-old and an older 'longtime partner' described as a romance was rejected editorially; generation now explicitly requires near-age romance peers, with optional romance only.
